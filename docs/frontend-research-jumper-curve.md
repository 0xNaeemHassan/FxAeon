# Frontend behavior review: Jumper and Curve

Read-only source audit, using current default-branch commits as pinned snapshots. Scope was targeted: swap/router flow, query policies, balance reads, approvals, and fee presentation; no clone, dependency install, browser run, or tests. Jumper's app source delegates its main swap widget. I resolved the exact installed package, but its source is not published in the public app repo and its GitHub Packages tarball is not anonymously readable; widget-internal quote debounce and approval sequencing therefore remain unverified.

## What the source shows

### Jumper / LI.FI

Jumper's main widget is an integration, not its own quote form: [`Widget.tsx` imports and renders `LiFiWidget` from `@jumperexchange/widget`](https://github.com/jumperexchange/jumper-exchange/blob/eee099c8390dc8841179f80eaed027756a447e66/src/components/Widgets/variants/base/Widget.tsx#L3-L6), [render/config](https://github.com/jumperexchange/jumper-exchange/blob/eee099c8390dc8841179f80eaed027756a447e66/src/components/Widgets/variants/base/Widget.tsx#L30-L40). The pinned lock resolves the declared range `^4.6.1` to exactly `@jumperexchange/widget@4.6.1` from `npm.pkg.github.com` ([manifest](https://github.com/jumperexchange/jumper-exchange/blob/eee099c8390dc8841179f80eaed027756a447e66/package.json#L26-L41), [lock resolution and tarball](https://github.com/jumperexchange/jumper-exchange/blob/eee099c8390dc8841179f80eaed027756a447e66/pnpm-lock.yaml#L1523-L1528)). The lock's dependency graph says that package uses `@lifi/sdk@4.2.0`, `@jumperexchange/widget-provider@4.2.2`, and `@jumperexchange/wallet-management@4.1.3` ([resolved package dependencies](https://github.com/jumperexchange/jumper-exchange/blob/eee099c8390dc8841179f80eaed027756a447e66/pnpm-lock.yaml#L12244-L12258)). The public Jumper repo contains no widget implementation; the referenced package tarball returned HTTP 401 without package credentials, and public npm returns 404 for `@jumperexchange/widget@4.6.1`. LI.FI's public [`@lifi/widget` repository](https://github.com/lifinance/widget) is a separate package/version (current audited package manifest says 4.7.1 and uses `@lifi/sdk` `^4.10.0`), so its current source is not source-matched to Jumper's 4.6.1 fork. Consequently the exact Jumper widget's quote debounce, allowance refresh, approval/execution sequence, and UI behavior cannot be asserted from public source; only the app wrapper's own behavior below is verified.

The app config passes an API URL and merged RPC configuration into widget/SDK config ([`useSharedConfigs.ts`](https://github.com/jumperexchange/jumper-exchange/blob/eee099c8390dc8841179f80eaed027756a447e66/src/components/Widgets/variants/widgetConfig/useSharedConfigs.ts#L62-L83)). Its general React Query defaults are 5-minute stale time and no polling, with focus/reconnect refetching ([`makeQueryClient.ts`](https://github.com/jumperexchange/jumper-exchange/blob/eee099c8390dc8841179f80eaed027756a447e66/src/app/lib/makeQueryClient.ts#L5-L22)); do not mistake those app-wide defaults for widget quote cadence.

For portfolio balances, Jumper uses LI.FI's EVM `getWalletBalances`; non-EVM balances are fetched in bounded batches (300 records, at most 5 parallel batches) ([balance fetcher](https://github.com/jumperexchange/jumper-exchange/blob/eee099c8390dc8841179f80eaed027756a447e66/src/providers/PortfolioProvider/lib/fetchBalancesForAddresses.ts#L67-L124), [batch limits and runner](https://github.com/jumperexchange/jumper-exchange/blob/eee099c8390dc8841179f80eaed027756a447e66/src/utils/batches/fetcher.ts#L27-L30), [execution](https://github.com/jumperexchange/jumper-exchange/blob/eee099c8390dc8841179f80eaed027756a447e66/src/utils/batches/fetcher.ts#L67-L89)). Those limits address a broad multi-chain portfolio, not a small fixed protocol-token set. A separate Dust converter has a serialized-input query key and two-minute quote cache ([hook](https://github.com/jumperexchange/jumper-exchange/blob/eee099c8390dc8841179f80eaed027756a447e66/src/components/composite/DustFlow/hooks/useDustComposerQuote.ts#L13-L52), [API/cache policy](https://github.com/jumperexchange/jumper-exchange/blob/eee099c8390dc8841179f80eaed027756a447e66/src/components/composite/DustFlow/dustComposerQuoteApi.ts#L43-L64)); its inspected hook does not show a debounce.

Jumper's fee breakdown aggregates route gas/fees and exposes provider/network/price-impact detail ([cost model](https://github.com/jumperexchange/jumper-exchange/blob/eee099c8390dc8841179f80eaed027756a447e66/src/components/composite/JumperWidget/components/NetworkCost/hooks.ts#L16-L93), [display](https://github.com/jumperexchange/jumper-exchange/blob/eee099c8390dc8841179f80eaed027756a447e66/src/components/composite/JumperWidget/components/NetworkCost/NetworkCost.tsx#L28-L45)). This is useful as a presentation reference for a routed, multi-provider swap; its numbers and route model are LI.FI-specific.

### Related public implementation: LI.FI Widget (not Jumper 4.6.1)

For implementation detail, I separately checked public [`lifinance/widget`](https://github.com/lifinance/widget) at default-branch commit `0b3811ce2492b385219659632fd157b3b4923c57`. Its package is `@lifi/widget@4.7.1`, which depends on `@lifi/sdk ^4.10.0` ([package manifest](https://github.com/lifinance/widget/blob/0b3811ce2492b385219659632fd157b3b4923c57/packages/widget/package.json#L1-L36), [SDK dependency](https://github.com/lifinance/widget/blob/0b3811ce2492b385219659632fd157b3b4923c57/packages/widget/package.json#L55-L73)); Jumper pins a distinct package `@jumperexchange/widget@4.6.1` whose SDK dependency is 4.2.0. This section describes the public LI.FI implementation only, not the private Jumper package.

The public LI.FI route hook debounces both input and target amounts for 500 ms ([`useRoutes.ts`](https://github.com/lifinance/widget/blob/0b3811ce2492b385219659632fd157b3b4923c57/packages/widget/src/hooks/useRoutes.ts#L113-L125)), keys quote queries on sender/receiver, chains, token addresses, both amounts, slippage, route allow/deny lists, priority, fees, and execution options ([query key](https://github.com/lifinance/widget/blob/0b3811ce2492b385219659632fd157b3b4923c57/packages/widget/src/hooks/useRoutes.ts#L213-L277)), then calls SDK route/relayer quote APIs ([route calls](https://github.com/lifinance/widget/blob/0b3811ce2492b385219659632fd157b3b4923c57/packages/widget/src/hooks/useRoutes.ts#L456-L545)). Routes are stale-refetched every 60 seconds, preserve previous data when configured, and retry failures up to a bounded count ([route query policy](https://github.com/lifinance/widget/blob/0b3811ce2492b385219659632fd157b3b4923c57/packages/widget/src/hooks/useRoutes.ts#L614-L635)); the same constant sets the freshness window ([definition](https://github.com/lifinance/widget/blob/0b3811ce2492b385219659632fd157b3b4923c57/packages/widget/src/hooks/useRoutes.ts#L40-L45)). Token balances are fetched per account+chain and polled at 32 seconds with previous data retained and retries disabled so a slow chain does not reshuffle the list late ([`useTokenBalancesQueries.ts`](https://github.com/lifinance/widget/blob/0b3811ce2492b385219659632fd157b3b4923c57/packages/widget/src/hooks/useTokenBalancesQueries.ts#L9-L58)).

The widget's route list permits a click only when the wallet is connected and the destination constraints are met; selection saves the route and navigates to a transaction-execution/review page ([`RoutesPage.tsx`](https://github.com/lifinance/widget/blob/0b3811ce2492b385219659632fd157b3b4923c57/packages/widget/src/pages/RoutesPage/RoutesPage.tsx#L62-L108)). The execution hook hands the route to `@lifi/sdk` `executeRoute` and surfaces route updates/events ([`useRouteExecution.ts`](https://github.com/lifinance/widget/blob/0b3811ce2492b385219659632fd157b3b4923c57/packages/widget/src/hooks/useRouteExecution.ts#L127-L160)). The corresponding exact SDK 4.10.0 source at `lifinance/sdk` commit `4ee42651e59c0b8dba8aa5ab03e1177f65258bfc` confirms that route steps run sequentially ([`execution.ts`](https://github.com/lifinance/sdk/blob/4ee42651e59c0b8dba8aa5ab03e1177f65258bfc/packages/sdk/src/core/execution.ts#L83-L160)); its Ethereum pipeline checks allowance, then conditionally sets it before balance check, transaction preparation, user execution, and receipt/status wait ([task order](https://github.com/lifinance/sdk/blob/4ee42651e59c0b8dba8aa5ab03e1177f65258bfc/packages/sdk-provider-ethereum/src/core/EthereumStepExecutor.ts#L137-L195)). The allowance task skips approval when sufficient, pauses if interaction is unavailable, otherwise submits approval and waits for its receipt before continuing ([set allowance task](https://github.com/lifinance/sdk/blob/4ee42651e59c0b8dba8aa5ab03e1177f65258bfc/packages/sdk-provider-ethereum/src/core/tasks/EthereumSetAllowanceTask.ts#L12-L18), [approval and receipt wait](https://github.com/lifinance/sdk/blob/4ee42651e59c0b8dba8aa5ab03e1177f65258bfc/packages/sdk-provider-ethereum/src/core/tasks/EthereumSetAllowanceTask.ts#L55-L124)). This is a useful route-aggregator reference, but automatic SDK orchestration over arbitrary bridge/swap routes differs from FxAeon's narrowly scoped, f(x)-SDK-planned protocol calls.

Public LI.FI's fee helper groups gas and provider fees by chain, totals the USD amounts, and distinguishes fee items marked included vs. not included ([`fees.ts`](https://github.com/lifinance/widget/blob/0b3811ce2492b385219659632fd157b3b4923c57/packages/widget/src/utils/fees.ts#L10-L37), [provider fee filtering](https://github.com/lifinance/widget/blob/0b3811ce2492b385219659632fd157b3b4923c57/packages/widget/src/utils/fees.ts#L71-L105)); its tooltip labels network and provider costs separately ([`FeeBreakdownTooltip.tsx`](https://github.com/lifinance/widget/blob/0b3811ce2492b385219659632fd157b3b4923c57/packages/widget/src/components/FeeBreakdownTooltip.tsx#L23-L49)). That's a design reference for itemizing costs, not a cost calculation to transplant into f(x).

### Curve

Curve's router swap debounces form input for 350 ms before quote work ([shared debounce and duration](https://github.com/curvefi/curve-frontend/blob/81b6ea09d5a6f4ccd895eac62ad8c423981b09c6/packages/ui/src/hooks/useDebounce.ts#L16-L36), [350 ms constant](https://github.com/curvefi/curve-frontend/blob/81b6ea09d5a6f4ccd895eac62ad8c423981b09c6/packages/ui/src/features/themes/design/0_primitives.ts#L146-L165), [router form input](https://github.com/curvefi/curve-frontend/blob/81b6ea09d5a6f4ccd895eac62ad8c423981b09c6/apps/main/src/dex/components/PageRouterSwap/index.tsx#L506-L529)). Its query timings are centrally classified by urgency ([stale/refetch durations](https://github.com/curvefi/curve-frontend/blob/81b6ea09d5a6f4ccd895eac62ad8c423981b09c6/packages/ui/src/features/queries/query-types.ts#L14-L43), [feature categories](https://github.com/curvefi/curve-frontend/blob/81b6ea09d5a6f4ccd895eac62ad8c423981b09c6/packages/ui/src/features/queries/query-categories.ts#L11-L39)). The active router refreshes quotes at a 15-second cadence and stops interval work when the page is hidden ([router interval](https://github.com/curvefi/curve-frontend/blob/81b6ea09d5a6f4ccd895eac62ad8c423981b09c6/apps/main/src/dex/components/PageRouterSwap/index.tsx#L419-L472), [visibility hook](https://github.com/curvefi/curve-frontend/blob/81b6ea09d5a6f4ccd895eac62ad8c423981b09c6/packages/ui/src/hooks/usePageVisibleInterval.ts#L7-L30)). Its quote source also changes with wallet connectivity: disconnected users use API routes; connected users use the Curve router, with parameter-rich route-query keys ([router choice](https://github.com/curvefi/curve-frontend/blob/81b6ea09d5a6f4ccd895eac62ad8c423981b09c6/apps/main/src/dex/components/PageRouterSwap/index.tsx#L110-L129), [API query key/inputs](https://github.com/curvefi/curve-frontend/blob/81b6ea09d5a6f4ccd895eac62ad8c423981b09c6/packages/evm-ui/src/queries/router-api/router-api.query.ts#L68-L149)).

Curve's large token-selector balance prefetch collapses balance/decimals reads into one multicall, then seeds individual query entries; the source specifically motivates this with selectors containing 1,000+ tokens and rate-limited public RPCs ([`useTokenBalance.ts`](https://github.com/curvefi/curve-frontend/blob/81b6ea09d5a6f4ccd895eac62ad8c423981b09c6/packages/evm-ui/src/hooks/useTokenBalance.ts#L188-L231)). For approvals, its QuickSwap UI exposes approval and swap as separate steps and does not enable swap until approved ([step UI](https://github.com/curvefi/curve-frontend/blob/81b6ea09d5a6f4ccd895eac62ad8c423981b09c6/apps/main/src/dex/components/PageRouterSwap/index.tsx#L288-L326), [button gating](https://github.com/curvefi/curve-frontend/blob/81b6ea09d5a6f4ccd895eac62ad8c423981b09c6/apps/main/src/dex/components/PageRouterSwap/index.tsx#L392-L400)); approval success refreshes quote, gas and approval state before the user separately submits swap ([store flow](https://github.com/curvefi/curve-frontend/blob/81b6ea09d5a6f4ccd895eac62ad8c423981b09c6/apps/main/src/dex/store/createQuickSwapSlice.ts#L340-L429)). Its exchange-rate component labels the displayed rate as fee-inclusive ([`DetailInfoExchangeRate.tsx`](https://github.com/curvefi/curve-frontend/blob/81b6ea09d5a6f4ccd895eac62ad8c423981b09c6/apps/main/src/dex/components/PageRouterSwap/components/DetailInfoExchangeRate.tsx#L15-L23)); inspected QuickSwap summary shows gas, slippage, impact and rate but no separate fee line ([summary](https://github.com/curvefi/curve-frontend/blob/81b6ea09d5a6f4ccd895eac62ad8c423981b09c6/apps/main/src/dex/components/PageRouterSwap/index.tsx#L611-L641)).

## Transfer to FxAeon

FxAeon already implements several of the underlying RPC patterns: wallet query keys include session, chain and lowercase address, with 15-second stale time, one-minute cache GC, focus/reconnect refetch, and background polling disabled ([`walletQueries.ts`](../apps/mini-app/src/lib/web3/walletQueries.ts#L15-L45)); protocol balances use wagmi `readContracts` with per-token failure handling ([same file](../apps/mini-app/src/lib/web3/walletQueries.ts#L61-L97)). Exact portfolio reads are also batched ([same file](../apps/mini-app/src/lib/web3/walletQueries.ts#L130-L188)). The provider polls exact balances at 60 seconds and disables the interval for indexed discovery; chain pulse is a fallback for exact balances ([`WalletDataProvider.tsx`](../apps/mini-app/src/components/WalletDataProvider.tsx#L214-L225)). Prices and the live market stream are visibility/online aware already ([`PriceProvider.tsx`](../apps/mini-app/src/components/PriceProvider.tsx#L137-L167), [socket](../apps/mini-app/src/components/PriceProvider.tsx#L169-L195)). The working tree now shares the legacy balance key/query function for Ethereum canonical portfolio rows so those observers join the same in-flight read ([`walletQueries.ts`](../apps/mini-app/src/lib/web3/walletQueries.ts#L188-L211)); Base uses a separate canonical query because its reads differ.

FxAeon keeps a protocol-specific approval boundary: the runner re-simulates remaining calls after a confirmed approval and refreshes an expired gas quote without raising reviewed fee ceilings ([`runner.ts`](../apps/mini-app/src/lib/fx/runner.ts#L487-L549)); review shows approval count and exact spender/amount ([`ActionReview.tsx`](../apps/mini-app/src/components/ActionReview.tsx#L258-L282), [prepared tx detail](../apps/mini-app/src/components/ActionReview.tsx#L458-L474)). Therefore:

1. **Keep FxAeon's existing route warm-up; do not add another debounce layer by default.** Trade schedules best-effort plan prefetch 220 ms after a valid edit, only while foreground/online and with ticket/session/form fields captured ([`trade/page.tsx`](../apps/mini-app/src/app/trade/page.tsx#L406-L467)). Its in-memory `RoutePrefetchStore` holds one exact-input entry for 10 seconds ([TTL and descriptor key](../apps/mini-app/src/lib/fx/routePrefetch.ts#L8-L26), [full-key construction](../apps/mini-app/src/lib/fx/routePrefetch.ts#L38-L74)); it revalidates the current block and form descriptor before reuse ([validation](../apps/mini-app/src/lib/fx/routePrefetch.ts#L132-L145)). This is the same class of latency optimization as Curve's debounce/prefetch, adapted to a protocol action preview. Add a separate debounce only if measurements show redundant quote work outside this Trade flow.
2. **Keep the current cache/batching/visibility design.** Curve's 1k-token multicall prefetch and fine-grained global query taxonomy solve a materially larger DEX. They would add policy surface without lowering FxAeon's present fixed-list RPC workload.
3. **Keep the current approval and fee-review sequencing.** Use Curve/Jumper as UX references for legible route cost / fee-inclusive rate labels, while preserving the current f(x) SDK quote, reviewed ceilings and user-wallet confirmation flow. No generic widget or router is a safe substitute for f(x)-specific transaction plans.
